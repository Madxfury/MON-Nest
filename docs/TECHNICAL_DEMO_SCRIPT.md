# MON-Nest technical demo — maximum 3 minutes

**Recording gate:** Record the booking steps only after the Monad Testnet booking contract is deployed, all 68 listing reads return 0 MON and available, and a real booking receipt has been verified on the public site. Keep the product on screen throughout; do not use slides or a code walkthrough. Have a renter wallet with a little testnet MON for gas. Use a separate browser or private window to show shared availability. These homes are illustrative; the reservation does not grant a tenancy.

| Time | Show on screen | Say |
| --- | --- | --- |
| 0:00–0:22 | Open `mon-nest.vercel.app`; scroll from the homepage to the 68-home catalog. | “MON-Nest is a rental booking prototype for people who want a clear answer to a familiar problem: is this home actually available, and what happens after I book? We built it for renters who need a simple reservation flow. All 68 illustrated homes are free testnet listings, so we can demonstrate the mechanics without charging rent.” |
| 0:22–0:43 | Filter by city, open an available home, point to its 0 MON price, deposit, and history. | “Search and choose a home like any marketplace. Each card gets its availability from a Monad Testnet contract, and the detail page shows its booking history. These are illustrative homes, not real rental offers.” |
| 0:43–1:12 | Connect a renter account, open the booking review, show 0 MON rent and deposit, gas estimate, network, contract and broker destination. | “The wallet is our account. Mera passkeys are integrated for account creation and signing; an existing wallet works too. Before signing, MON-Nest rechecks the home, the broker destination, and the exact 0 MON amount, then simulates the transaction and estimates network gas.” |
| 1:12–1:45 | Approve in the wallet, wait for confirmation, open the transaction receipt. | “I approve a real Monad Testnet transaction. The contract accepts one active booking for this listing, records my wallet and a 30-day expiry, and emits a public event. The booking sends 0 MON; my wallet pays only testnet gas.” |
| 1:45–2:08 | Show the card switch to **Rented**. Refresh in a second browser or disconnected window, then open Profile → Your bookings. | “The status is shared, so another visitor sees Rented too. My profile shows the booking and receipt; the property page keeps its event history. When the 30 days expire, the listing can be booked again.” |
| 2:08–2:37 | Scroll to **What powers the experience**. | “Alchemy serves Monad Testnet reads and transaction preflight from a server-side RPC adapter. Envio event handlers are built for bookings and the broader rental protocol; hosting the indexer is still pending. The property registry, escrow, jury, reputation and Chainlink CRE workflow have local contract tests, but are not part of this live booking. Aurora Intents has a live route checker; it currently does not advertise Aurora Testnet to Monad Testnet, so cross-chain funding is disabled.” |
| 2:37–3:00 | Return to the booking receipt and public Rented status. | “Our primary track is Consumer Products & Payments: familiar home discovery with a verifiable reservation underneath. The next step is testing the flow with renters and property partners, then validating real listings and expanding into protected rent escrow. Today’s proof is the confirmed onchain booking and the same availability seen by everyone.” |

**Before recording:** Use a home that is currently **0 MON · Available**. Do one real booking, wait for a successful receipt, and check the public state in a second browser. If the contract is not deployed, the page says **Booking unavailable**; do not narrate an onchain booking that has not happened. If Mera has not passed a real device ceremony, demonstrate with the existing wallet and describe Mera as an integrated option rather than a verified live passkey flow. Do not claim Envio hosting, CRE deployment, Aurora bridging, real tenancies, user traction, or awarded bounties.
